# Part 1 frontend audit — AI Portal and destination overlap

Audit source: `work/portal-handover/gate-ec-ai-portal-handover` from the supplied ZIP. Destination source: `outputs/gate-terminal/dist`. This is a source audit, not an assertion that the imported application has been deployed or that its services are currently available. No portal features were migrated by this audit.

## Actual implementation and entry points

- `client/src/main.tsx` mounts React 19, TanStack Query 5 and tRPC 11 with a same-origin `/api/trpc` batched link and SuperJSON. Cookies are included. The preview-only Manus token fallback reads `manus-cookie` from sessionStorage and forwards a Bearer token.
- `client/src/App.tsx:18` declares Wouter `Switch`/`Route` entries inside **PortalLayout**, imported from `pages/Portal.tsx`. Canonical routes are `/`, `/predictor`, `/admissions`, `/institutes`, `/psu-cutoffs`, `/planner`, `/mocks`, `/alerts`, `/pyqs`, `/forum`, `/dashboard`, `/dashboard/settings`, `/admin/metrics`; compatibility aliases are `/rank-predictor` and `/pyq-bank`.
- The small page modules for predictor/admissions/PSU/PYQ/forum/planner/mocks mostly re-export components from the 183-line, heavily compressed `pages/Portal.tsx`. They are not independently isolated domain implementations. `InstitutesPage.tsx` and `MetricsPage.tsx` are substantial separate implementations.
- `components/DashboardLayout.tsx` is **not used by App.tsx or the actual PortalLayout**. It is scaffold code with Page 1 and Page 2 navigation (`/some-path`), a resizeable 200–480px sidebar and authentication gate. Its existence is not evidence that the portal uses that shell.
- `Portal.tsx:182` implements the actual shell as a public marketing header/footer and a keyed route container. Its candidate workspace adds a second nested sidebar in `WorkspaceView` (`:109`). Copying it into the Research Terminal would create the disconnected double-shell experience the request forbids.
- `README.md` is **absent**, despite being listed and referenced by `handover/HANDOVER.md`. The handover, package.json, configuration and other docs can be read; the missing README remains a packaging/documentation gap.

## Concrete source defects / misleading states to address before Part 2 activation

1. **Hardcoded live-looking hero figure:** `Portal.tsx:49` renders `AIR 1,3xx` under LIVE MODEL SURFACE and the text “from a 52.0-mark input” whenever the overview has any historical years. It does not call the rank predictor with 52.0 and is illustrative, not live model output. Do not copy it into the real-data terminal overview.
2. **Dashboard actions do not navigate:** `WorkspaceView` passes `onTab={routeFor}`; `routeFor` only returns a path string. DashboardOverview's Open alerts/Open planner/Create a plan buttons call it but ignore the result. Native sidebar `<Link>` navigation works separately. Fix when migrating the actual dashboard, not by activating placeholder routes now.
3. **Rank handoff lost:** RankPredictor links to `/admissions?rank=${value.rank}`, but Admissions uses `useState("1200")` with no URL-query parsing.
4. **Insufficient error/loading states:** many reference/private queries fall back to `[]` and render empty lists on failure; RequireLogin ignores loading. A network error must not imply there are no records. Metrics handles only some errors.
5. **Unsupported theme claim:** `App.tsx` passes `ThemeProvider defaultTheme="light"` with default `switchable=false`; no routed theme switch is rendered, and index.css hardcodes light colours throughout with no `.dark` theme overrides. Do not import the portal styling as a ready dual-theme system.
6. **Inconsistent evidence concepts:** hardcoded Verified badges can imply more than supplied official/reference provenance or the user's own manual entry. Destination confidence and evidence must remain distinct types.
7. **Privacy/runtime coupling:** useAuth writes the complete `auth.me` object to `manus-runtime-user-info` localStorage; main.tsx understands preview tokens mirrored to sessionStorage. Do not transfer preview identity persistence into the public research service.
8. **Metrics chart/interaction caveats:** minimum 6%-height bars visually inflate zero-event days; feature rows declare role=button/tabIndex but only hover/focus events, no activation action. `AnimatedNumber` runs a 650ms requestAnimationFrame animation regardless of reduced motion. Preserve aggregate privacy while replacing these UI conventions.
9. **Historical documentation is not current proof:** docs claim an August 2026 validation run and seven test files/22 tests; current archive contains ten test files. The audit did not rerun or adopt those old results. Handover says live rows/secrets are excluded; source presence alone cannot establish API availability.

### Runtime / seed boundaries

`server/db.ts` seeds five public reference documents (`gate-history`, `curve-2026`, `iisc-cutoffs`, `iitm-cutoffs`, `coap-history`) from the included public JSON and five official-paper links. This does **not** seed candidate mocks, saved predictions, study plans, reminders, forum threads/replies or votes. `getProfile` initializes defaults only for an authenticated user. Public reference updates can create in-app alerts for existing opted-in profiles; seeding is therefore not a harmless client-only operation and should not be executed against a production personal database during Part 1.

A missing DATABASE_URL can lead some list functions to return `[]`, while mutations and profile reads throw. Destination adapters must represent `unavailable` explicitly rather than silently returning fake empty success. No live database or API connection was exercised in this audit.
