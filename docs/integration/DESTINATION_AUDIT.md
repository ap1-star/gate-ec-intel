# Part 1 destination audit — existing Research Terminal

Audit scope: actual local source in `outputs/gate-terminal`, at checkpoint `7f93d6c733737a03a4b9c3dc5522482b74bf7728`. No application source was changed for this audit. Uploaded portal features are assessed separately in the frontend/backend audit documents.

## Architecture and deployment facts

- `.openai/hosting.json` selects project `appgprj_6af5a0ff7a00819196fd4bf62194e4dd`, static directory `dist`. There is no destination `package.json`, React tree, Node API server, database connection, authentication implementation, scheduler or server-side secret store configured in this checkout.
- `dist/index.html` is a buildless entry point. It loads `interface.css` and 16 ordered classic JavaScript scripts: public research/difficulty/quality data; scoring and topic helpers; `terminal.js`, `quality.js`, `study.js`, `trading.js`, `atlas.js`, `workspace.js`; `v5-math.js`; `v5.js`; `ui-icons.js`; and `interface.js`.
- The numerical engine `window.V5Math` is a small pure module. Most legacy analytical functions and UI state are shared script-level bindings. `R` references `window.RESEARCH`; toughness and quality are joined by stable question ID.
- `routeFunctions` is declared in `v5.js:200` and subsequently overridden by `interface.js`. Hash changes drive route selection and reset pagination. Fifteen public routes are currently present.
- Presentation evolved through wrapper overrides. Earlier modules create DOM, attach delegated document handlers and wrap `render`, `subjects`, `questionList`, `difficulty`, `selectedQuestionRows` and exports. The final presentation render is in `interface.js`, with a final disclosure-state wrapper near its end. Scripts therefore remain order-dependent.
- The only active stylesheet is `interface.css`; the older CSS files remain in the static export but are not linked. Google Fonts is imported with system/Consolas fallbacks. Lucide SVG strings and license are local.
- Public response CSV processing happens only in the browser. Notes, theme, sidebar preference, table columns and saved views use `localStorage`; imported `responseData` is in-memory. These are device-local conveniences, not authenticated private account storage.
- The source helper owns pushing and packaging; Sites publishes an archive containing manifest plus static assets. Preserve the existing project identity and audience. No Worker/server output exists in this baseline.

## Invariants to preserve

1. Stable question IDs and all current public data, audit exports, scoring dimensions and provenance remain the baseline. Public build has official-source links rather than full redistributed scans/options; `R.questions.every(q=>q.public_text_policy && q.options==="{}")` is an existing tested policy. Root research/original assets must not be copied into served `dist` merely to populate a portal screen.
2. Baseline: 520 questions, 65/year, 100 marks/year, 800 overall, 2019–2026. Default difficulty cohort is 509 non-MTA questions. Labels are Easy <35, Moderate ≥35 and <65, Tough ≥65; changing labels does not change score. Score = weighted 0–4 concepts/reasoning/computation/integration/representation (25/25/20/20/10).
3. Classification, structural estimates, empirical observations and source review are different types. Corpus empirical item difficulty/IRT fields remain null. Source review coverage does not imply independent human certification or complete OCR correctness.
4. Annual subject descriptive calculations include zero-allocation years in the chosen research range. Single-year SD/CV are unavailable. Exact inference intentionally uses all eight papers and ignores global filters; local response analysis uses imported data; scenarios require complete compositions and ignore global subject selection. Do not normalize these intentionally different scopes into a misleading one-size-fits-all API.
5. Charts, linked record tables and exports must share selectors; keep MTA, confidence, topic-granularity, query, brush and issue-queue semantics. Clear context also clears the brushed-ID set.
6. Pure numerical definitions stay unchanged: n−1 variance, interpolated quantiles, tied Spearman ranks, seeded 32-bit LCG bootstrap, actual-year Theil–Sen slope, constant-variable nulls, normalized scenario totals, and baseline backtest definition.
7. Browser-local candidate input and notes are not authenticated private records. Future account services must require explicit, server-authorized write paths; never auto-upload local CSV/notes on sign-in.

## Reuse and incremental architecture recommendations

- Retain the buildless analytical runtime in Part 1. Add a single route/capability catalogue and framework-neutral shared components/tokens, with typed contracts in a non-served integration directory. A React portal can consume those contracts/components via adapters in Part 2. Merely copying the portal Vite app into a second subdirectory would create two disconnected products.
- Create a read-only `ResearchRepository`/selector facade over current datasets and stable IDs. Existing numerical functions are the source of truth; route adapters should call them rather than re-derive values.
- Keep public research and private candidate services in different modules/contracts. Model unavailable/unauthenticated/forbidden/error explicitly with discriminated results; do not stub a successful user or predictor response.
- Introduce one service transport boundary with no configured production endpoint in Part 1. Future server auth must validate sessions/ownership independently of client `ProtectedRoute`. Gate owner/admin catalogue entries by authoritative session capabilities; omit them now.
- Shared UI already present: AppShell, Sidebar, WorkspaceHeader, FilterBar, MetricCard, ChartPanel, ResearchTable, SegmentedControl, SearchDialog, DetailDrawer, EmptyState, SourceBadge. Missing useful primitives: explicit PageHeader, generic DataTable, ConfidenceBadge, LoadingSkeleton, ErrorState, ProtectedRoute. Shared chart palette/formatting is incomplete because original SVG functions still embed colors/text sizes.
- Introduce accessible component variants and data attributes without changing legacy IDs consumed by event delegation. Avoid mounting React into `#content` while legacy `document` listeners still own that DOM. A later React migration needs an explicit host adapter and scoped lifecycle cleanup.
- Keep route definitions for future modules but do not register empty renderers or expose them in command results as implemented. Current unknown hashes silently fall back to overview; a deliberate unavailable/not-found state is needed to prevent misleading future-route resolution.

## Source-level UX/control risks to address in Part 1

These are source observations, not claimed browser failures in this audit.

- **Blank startup:** `interface.css` hides `body` until `.ui-ready`; any exception before the final script render can leave no visible error. Add a real load/error boundary and a recoverable rendered error state.
- **Full DOM replacement and focus loss:** `render()` replaces sidebar, toolbar, content and context on most changes. Only some actions restore focus. Filters, tab switches, sidebar links and drawers require deliberate focus targets; retain active text-field selection in live search.
- **Mobile navigation accessibility:** open button lacks `aria-expanded`/`aria-controls`; the sidebar overlay is not a modal focus boundary. Escape closes visually but no explicit opener restoration is implemented. Add logical focus and an accessible close action.
- **Unknown/planned route fallback:** unsupported hash resolves to `monitor`. Do not allow planned private/admin routes to masquerade as implemented overview routes.
- **Empty exports:** header export is unconditional. On `responses`, exporting before import produces analysis:null. Gate route export capability by meaningful available data, with honest feedback.
- **Generic raw HTML slots:** ChartPanel/MetricCard/table helpers accept raw strings for valid SVG/markup; future API/user strings must be escaped or passed through a clearly named trusted-markup boundary. Do not insert portal form/community values through these slots.
- **Menu semantics:** popovers are divs of buttons/links and do not implement complete menu keyboard conventions. Either use ordinary labelled popovers with normal Tab order and focus return or implement the full menu pattern; avoid cosmetic ARIA roles without behavior.
- **Toolbar metadata:** dataset year/count is hardcoded in `WorkspaceHeader`; use actual dataset version/status values for the new shell. Do not label visual-source review as independent verification.
- **Filtered overview copy:** annual metric currently calls selected years “Complete master papers” even when review filtering selects a subset; use scope-aware wording. Question metric subtitle remains “EC + General Aptitude” under a single-subject scope.
- **Source-reader copy:** retained inspector text says “Open an image to zoom” although the public build shows an official PDF button, not a local image. Revise presentation text while retaining source links and policy.
- **Saved view validation/storage errors:** safeLoad handles parse exceptions, but valid JSON of the wrong shape may still break restore; safeSave silently swallows quota/blocked storage and UI can report saved. Validate structure and report persistence failure.
- **Legacy event coupling:** multiple handlers act on the same attribute/ID and wrappers replace previous renderers. Tests must cover final route adapters, not only legacy `difficulty()` markup; old “Challenge radar” is a previous topic-watchlist layout, not an additional mathematical engine.
- **Tooltip accessibility:** a shared role=tooltip exists, but focusable marks do not receive `aria-describedby`; only pointer/focus event state positions it. Ensure data remains available to assistive technology through accessible labels and explicit association.
- **CSS/typography:** tokens exist, but some captions are 8–9px and legacy charts have embedded colors. Review real rendered contrast/legibility in dark/light themes; source inspection cannot certify those properties.
